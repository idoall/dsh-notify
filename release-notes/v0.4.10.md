<h3 id="cn-v0410">DSH Notify 0.4.10</h3>

跟进 DSH `0.2.1-rc.4`，通知功能保持不变。

兼容 DeepSeek Harness `0.2.1-rc.4`；宿主版本范围仍为 `>=0.1.7-rc.1 <0.3.0`。

### ⚠️ 调整

- 补充 `0.2.1-rc.4` 的兼容性声明，不改变通知、提示音或交互行为。它绑定的包在 `0.2.1-rc.3` → `0.2.1-rc.4` 之间逐字节相同，唯一例外是 `dsh-client-ui-settings-general`，而那里只替换了界面显示的宿主版本号；负责拼装页面客户端入口图的 `dsh-client-modules` 也只改了发布元数据里的 commit 哈希。宿主侧的 `cordis`、`schemastery` 仍是 `4.0.5` / `3.18.5`。
- 重新校对中英文 README 的版本、徽章、兼容性表格与升级示例，并同步锁文件版本。

### ✅ 验证

- 已在运行的 `0.2.1-rc.4` 宿主上实测：`/plugins/dsh-notify/health` 返回 `guiAvailable: true`、`services.jobs: "reflected"`、`eventErrors: 0`；`/config`、`/sounds`、`/update` 均返回 200（版本检测读取真实 npm registry）。
- 客户端半边：页面启动图（85 个客户端条目）中包含 `@idoall/dsh-notify/client.js`，其构建产物返回 200，并带有 `settings.section`、`shell.overlay` 两个挂载点与 `dsh-notify-*` 标记。
- 全套静态检查、**112 个自动化测试**、构建与打包检查通过。
- 发布验收会下载 npm 上的发布包，与发布标签逐项核对文档、声明与构建产物，并要求 npm `latest` 与 GitHub Release 的版本一致。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.10
```

<h3 id="en-v0410">DSH Notify 0.4.10</h3>

Tracks DSH `0.2.1-rc.4` without changing notification behavior.

Compatible with DeepSeek Harness `0.2.1-rc.4`; the host requirement remains `>=0.1.7-rc.1 <0.3.0`.

### ⚠️ Changes

- Declares `0.2.1-rc.4` compatible without changing notifications, sounds, or interactions. Every package this plugin binds is byte-identical across `0.2.1-rc.3` → `0.2.1-rc.4` except `dsh-client-ui-settings-general`, which only substitutes the host version string it displays, and `dsh-client-modules` — the package that composes the page's client entry graph — changes only the commit hash in its release metadata. The host's `cordis` and `schemastery` remain `4.0.5` / `3.18.5`.
- Rechecks both READMEs for current versions, badges, compatibility rows, and upgrade examples, and synchronizes the lockfile version.

### ✅ Verified

- Measured on the running `0.2.1-rc.4` host: `/plugins/dsh-notify/health` answered `guiAvailable: true` with `services.jobs: "reflected"` and `eventErrors: 0`, and `/config`, `/sounds` and `/update` all answered 200, with the update check reading the real npm registry.
- Client half: the page's boot graph (85 client entries) lists `@idoall/dsh-notify/client.js`, and its served build answered 200 carrying the `settings.section` and `shell.overlay` registrations plus the `dsh-notify-*` markup.
- Full static checks, **112 automated tests**, build, and package checks pass.
- Release acceptance downloads the published npm tarball, compares documents and declarations with the release tag, and requires the npm `latest` and GitHub Release versions to agree.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.10
```
