<h3 id="cn-v0411">DSH Notify 0.4.11</h3>

跟进 DSH `0.2.2-alpha.2`，通知功能保持不变。

兼容 DeepSeek Harness `0.2.2-alpha.2`；宿主版本范围仍为 `>=0.1.7-rc.1 <0.3.0`。

### ⚠️ 调整

- 补充 `0.2.2-alpha.2` 的兼容性声明，不改变通知、提示音或交互行为。承载整个 `slots` 服务与两个挂载点的 `dsh-client-ui-renderer` 在 `0.2.1-rc.4` → `0.2.2-alpha.2` 之间逐字节相同；`dsh-client-ui-settings`、`dsh-jobs`、`dsh-client-ui-slots`、`dsh-tool-workflow` 与 `dsh-client-connection` 的宿主半边同样未变。有改动的六处都是叠加式、不经过通知调用路径：`dsh-host-webserver` 新增一种 resource 路由（`register(route)` 与 `{kind,path,handler}` 派发未变）、`dsh-client-ui-session` 新增一个 `whenAccess()`、`dsh-client-ui-layout` 新增六份语言包、`dsh-client-modules` 新增 `require.asset` 与 assets 路由、`dsh-client-ui-settings-general` 重排设置面板网格（挂载点的 `{close}` 参数未变）、`dsh-client-connection` 只新增一个浏览器传输类型。宿主侧 `cordis`、`schemastery` 升至 `4.0.6-alpha.1` / `3.18.6-alpha.1`，前者只改 fiber 配置生命周期，后者代码逐字节相同。
- 重新校对中英文 README 的版本、徽章、兼容性表格与升级示例，并同步锁文件版本。

### ✅ 验证

- 已在运行的 `0.2.2-alpha.2` 宿主上实测（加载的是 `0.4.10` 构建）：`/plugins/dsh-notify/health` 返回 `guiAvailable: true`、`services.jobs: "reflected"`、`eventErrors: 0`；`/config`、`/sounds`、`/update` 均返回 200（版本检测读取真实 npm registry）。profile 中没有为该插件授予任何精确版本豁免。
- 客户端半边：页面启动图包含 `@idoall/dsh-notify/client.js`，其构建产物返回 200；在真实浏览器中打开 设置 → 通知，通知显示 / 提示音 / 任务提醒 / 预览与自测 均正常渲染，预览会向 `.dsh-notify-frame` 送出真实卡片，控制台无报错。390px 视口下设置区没有横向溢出，Toast 满宽显示。
- 全套静态检查、**112 个自动化测试**、构建与打包检查通过。
- 发布验收会下载 npm 上的发布包，与发布标签逐项核对文档、声明与构建产物，并要求 npm `latest` 与 GitHub Release 的版本一致。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.11
```

<h3 id="en-v0411">DSH Notify 0.4.11</h3>

Tracks DSH `0.2.2-alpha.2` without changing notification behavior.

Compatible with DeepSeek Harness `0.2.2-alpha.2`; the host requirement remains `>=0.1.7-rc.1 <0.3.0`.

### ⚠️ Changes

- Declares `0.2.2-alpha.2` compatible without changing notifications, sounds, or interactions. `dsh-client-ui-renderer`, which owns the whole `slots` service and both seats, is byte-identical across `0.2.1-rc.4` → `0.2.2-alpha.2`, as are `dsh-client-ui-settings`, `dsh-jobs`, `dsh-client-ui-slots`, `dsh-tool-workflow` and `dsh-client-connection`'s host half. The six packages that did change are all additive and off the notification call path: a second `resource` route style in `dsh-host-webserver` (`register(route)` and the `{kind,path,handler}` dispatch are unchanged), one `whenAccess()` in `dsh-client-ui-session`, six locale dictionaries in `dsh-client-ui-layout`, `require.asset` and the assets route in `dsh-client-modules`, a settings-panel grid restyle in `dsh-client-ui-settings-general` (the seat's `{close}` props are unchanged), and one browser-transport type in `dsh-client-connection`. The host's `cordis` and `schemastery` moved to `4.0.6-alpha.1` / `3.18.6-alpha.1` — the former changes only the fiber config lifecycle, the latter's code is byte-identical.
- Rechecks both READMEs for current versions, badges, compatibility rows, and upgrade examples, and synchronizes the lockfile version.

### ✅ Verified

- Measured on the running `0.2.2-alpha.2` host, which was already serving this plugin's `0.4.10` build: `/plugins/dsh-notify/health` answered `guiAvailable: true` with `services.jobs: "reflected"` and `eventErrors: 0`, and `/config`, `/sounds` and `/update` all answered 200, with the update check reading the real npm registry. The profile holds no exact-version exemption for this plugin.
- Client half: the page's boot graph lists `@idoall/dsh-notify/client.js` and its served build answered 200; in a real browser, Settings → Notifications rendered the 通知显示 / 提示音 / 任务提醒 / 预览与自测 sections, its preview delivered a real card into `.dsh-notify-frame`, and the console stayed clean. At a 390px viewport the section fits with no horizontal overflow and the toast is full-width.
- Full static checks, **112 automated tests**, build, and package checks pass.
- Release acceptance downloads the published npm tarball, compares documents and declarations with the release tag, and requires the npm `latest` and GitHub Release versions to agree.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.11
```
