声明兼容 DeepSeek Harness `0.2.1-rc.2`（`0.2.1` 线的第一个 RC），代码零改动。

<h3 id="cn-v047">🔌 兼容性</h3>

- 兼容 DeepSeek Harness `0.2.1-rc.2`：`dsh.compatibility.dshReleases` 增加这一行；`>=0.1.7-rc.1 <0.3.0` 本来就接纳它，范围无需放宽，也不需要版本豁免。
- `0.2.1-rc.2` 不需要代码改动：插件绑定的十几个包里只有一个有差异——`dsh-client-ui-settings-general`，且只差它界面显示的宿主版本号；`settings.section` 与 `shell.overlay` 座位未动。
- 宿主侧 `cordis` 与 `schemastery` 从 `4.0.5-alpha.2` / `3.18.5-alpha.2` 转正为 `4.0.5` / `3.18.5`，两者与本插件此前运行过的 alpha 版本**逐字节相同**（仅 `package.json` 不同），仍在本插件的 `^4.0.4` / `^3.18.4` 范围内。
- `0.2.1-rc.1` **没有**被声明：这台机器从未启动过它，而那个列表里的每一项都代表一次真实启动，不是语义化猜测。

<h3 id="cn-v047">✅ 验证</h3>

- 真实运行的 `0.2.1-rc.2` 上，加载器只拒了 `browser-use` 与 `browser-use-playwright-mcp` 两行，本插件未被拒载，也没有动用任何版本豁免。
- 宿主半边实测：`/health` 报 `guiAvailable: true`、`eventErrors: 0`；`/config`、`/sounds`、`/update` 均返回 200。
- 客户端半边实测：页面客户端插件包内含 `@idoall/dsh-notify/client.js`，实际下发的合并包 200，带 `settings.section` 与 `shell.overlay` 注册。
- `npm run verify`：静态检查、**110/110** 测试、构建、打包前置检查。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.7
```

本版只有兼容性声明变化，在 `0.2.1-rc.2` 上运行的 `0.4.6` 功能上无需升级；这条命令只是把 npm 上的版本与声明同步到最新。

<h3 id="en-v047">🔌 Compatibility</h3>

- Compatible with DeepSeek Harness `0.2.1-rc.2`, the first release candidate of that line: `dsh.compatibility.dshReleases` gains that line; the existing `>=0.1.7-rc.1 <0.3.0` requirement already admitted it, so no range widening and no exemption were needed.
- `0.2.1-rc.2` needs no code change: of the packages this plugin binds, exactly one differs, and `dsh-client-ui-settings-general` differs only in the host version string it displays; the `settings.section` and `shell.overlay` seats are untouched.
- The host's `cordis` and `schemastery` promoted from `4.0.5-alpha.2` / `3.18.5-alpha.2` to stable `4.0.5` / `3.18.5` — **byte-identical to the alphas** apart from `package.json`, and still inside this plugin's `^4.0.4` / `^3.18.4` ranges.
- `0.2.1-rc.1` is deliberately **not** declared: this machine never booted it, and every entry in that list names a real boot rather than a semver guess.

<h3 id="en-v047">✅ Verification</h3>

- On a real `0.2.1-rc.2` runtime the loader refused only the `browser-use` and `browser-use-playwright-mcp` rows: this plugin was neither refused nor granted an exact-version exemption.
- Host half measured live: `/health` reported `guiAvailable: true` and `eventErrors: 0`; `/config`, `/sounds` and `/update` all answered 200.
- Client half measured live: the page lists `@idoall/dsh-notify/client.js` in its plugin bundle, and the served combo bundle answered 200 with the `settings.section` and `shell.overlay` registrations.
- `npm run verify`: static source checks, **110/110** tests, build, and package precondition checks.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.7
```

This release changes compatibility declarations only; a `0.4.6` already running on `0.2.1-rc.2` needs no functional upgrade, and this command merely syncs the npm version and declaration.
