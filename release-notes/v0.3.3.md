<h3 id="cn-v033">适配 DeepSeek Harness 0.1.7-rc.1</h3>

### 这次解决了什么

`0.3.3` 让插件能在 DSH `0.1.7-rc.1` 上加载并工作。`0.3.2` 是对着 `0.1.6-alpha.1` 验证的；DSH 0.1.7 改了三处本插件依赖的公开缝，不升级就会静默失效：

1. **后台任务完成不再通知**：`jobs.onJobDone` 已从注册表移除，换成单一生命周期事件流。
2. **提问卡片无法按 tool/result 结算**：工具结果身份扁平化到 tool-role 消息上，`message.content` 里不再有 `tool-result` 块。
3. **卡片内回答按钮消失**：客户端 `uiSession.pendingInteractions` 已换成统一的 `sessionStatus` 快照，可回答对象嵌在 `pendingInteraction` 下。

### 适配方式

- **后台任务走 `jobs.events.subscribe({ owners: 'all' })`**：只处理 `settled` 且 `awaited !== true` 的结算；已被 `wait()` 领取的结算不再弹卡。没有事件流的旧 Host 仍回退到 `onJobDone`。
- **工具结果读取扁平化消息**：权威字段是 `message.toolCallId` 与 `message.isError`；嵌套的 `tool-result` 内容块只作为旧 Host 回退。
- **卡片内回答读取 `uiSession.sessionStatus`**：优先读 0.1.7 的 Session 状态快照；旧的 `pendingInteractions` 映射仍可解析。
- **兼容性变成加载门槛**：`dsh.engines.dsh` 与每一个 `@deepseek-ai/dsh-*` peer 都声明 `>=0.1.7-rc.1 <0.2.0`。`@deepseek-ai/schemastery` 改为 peer，这样 `link:` 安装能从当前 DSH 安装解析 Host 半依赖。

### 对使用者的可观察行为

- DSH `0.1.7-rc.1` 上：插件会加载；设置里出现「通知」；自测 Toast 会出现在设置对话框之上。
- 更早的 DSH（含 `0.1.6-alpha.1`）：请继续用插件 `0.3.2`。`0.3.3` 会在 profile 加载时被拒绝。
- 后台任务完成通知仍默认关闭；开启后只对未被 `wait()` 领取的结算弹卡。

### 验证

- 新增 jobs 事件流回归：注入路径走 `events`；`awaited` 结算不弹卡；旧 `onJobDone` 仍是回退。
- 新增扁平化 `tool/result` 回归：按 `message.toolCallId` 结算；旧嵌套块仍可关闭交互。
- 新增 Session 状态快照回归：0.1.7 形状与旧映射都能解析到可回答对象。
- 在未重启的 DSH `0.1.7-rc.1` 上做 `link:` 热挂载：Host 路由存在、客户端 bundle 注册、设置「通知」页渲染、四种状态自测叠在设置对话框之上。
- 完整发布验证通过：静态检查、**86 项自动化测试**、Host/Client 构建及 npm 包前置检查。

### 已知边界

- 通知记录仍是进程与页面内存状态；已结算历史不会在刷新、浮层重挂载或 DSH 重启后重播。
- 未给 profile 配置绝对 `dataDir` 时，偏好只保存在当前进程（设置页会显示「设置不落盘」）。
- 侧栏 `sidebar.footer.action` 上既有的 React #130 崩溃与本插件无关：摘掉 `@idoall/dsh-notify` 后错误仍在。

<h3 id="en-v033">Adapted to DeepSeek Harness 0.1.7-rc.1</h3>

### What this release solves

`0.3.3` makes the plugin load and work on DSH `0.1.7-rc.1`. `0.3.2` was verified against `0.1.6-alpha.1`. DSH 0.1.7 changed three public seams this plugin used, so staying on `0.3.2` would fail silently:

1. **Background-job completions stopped notifying**: `jobs.onJobDone` left the registry in favour of one lifecycle event stream.
2. **Question cards could not settle from `tool/result`**: tool-result identity moved onto the tool-role message; `message.content` no longer carries a `tool-result` block.
3. **In-toast answer buttons disappeared**: the client `uiSession.pendingInteractions` map was replaced by the unified `sessionStatus` snapshot, with the answerable object nested under `pendingInteraction`.

### How it is adapted

- **Jobs follow `jobs.events.subscribe({ owners: 'all' })`**: only `settled` events that were not already awaited become cards. Hosts that still expose `onJobDone` remain a fallback.
- **Tool results read the flattened message**: `message.toolCallId` and `message.isError` are authoritative; the nested `tool-result` content block is only a fallback for an older host.
- **In-toast answers read `uiSession.sessionStatus`**: the 0.1.7 Session status snapshot is preferred; the older `pendingInteractions` map is still parsed.
- **Compatibility is a load-time requirement**: `dsh.engines.dsh` and every `@deepseek-ai/dsh-*` peer declare `>=0.1.7-rc.1 <0.2.0`. `@deepseek-ai/schemastery` is a peer so a `link:` install resolves the Host half from the running installation.

### Observable behavior

- On DSH `0.1.7-rc.1`: the plugin loads; **Settings → Notifications** appears; a self-test Toast stack appears above the settings modal.
- On earlier DSH (including `0.1.6-alpha.1`): stay on plugin `0.3.2`. `0.3.3` is refused at profile load.
- Background-job completion notifications remain off by default; when enabled, only unawaited settlements raise a card.

### Verification

- Jobs event-stream regression: the injected path uses `events`; awaited settlements stay silent; `onJobDone` remains the fallback.
- Flattened `tool/result` regression: settlement follows `message.toolCallId`; a nested pre-0.1.7 block still closes the interaction.
- Session status snapshot regression: both the 0.1.7 shape and the older map resolve to an answerable interaction.
- Live `link:` install on DSH `0.1.7-rc.1` without restart: Host routes present, client bundle registered, Notifications settings rendered, four-tone self-test stacked above the settings modal.
- Full release verification passed: static checks, **86 automated tests**, Host/Client build, and npm package precondition checks.

### Known boundary

- Notification records remain process- and page-memory state. Settled history is not replayed after a refresh, overlay remount, or DSH restart.
- Without an absolute `dataDir` in the profile patch, preferences stay in-process (the settings page reports they are not persisted).
- A pre-existing React #130 crash in `sidebar.footer.action` is unrelated: it remains after `@idoall/dsh-notify` is removed from the profile.
