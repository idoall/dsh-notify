声明兼容 DeepSeek Harness `0.2.1-alpha.3`，代码零改动；正在运行的 `0.4.3` 本来就已在 `0.2.1-alpha.3` 上正常通知。

<h3 id="cn-v044">🔌 兼容性</h3>

- 兼容 DeepSeek Harness `0.2.1-alpha.3`：`dsh.compatibility.dshReleases` 增加这一行；`>=0.1.7-rc.1 <0.3.0` 本来就接纳它，范围无需放宽。
- `0.2.1-alpha.3` 不需要代码改动：逐一比对插件绑定的每个接口，全部未变——`requestRejection`、`webServer.register`/`tapIndex`、`settings.section` 与 `shell.overlay` 座位、`slots.inject`、`uiSession.sessionStatus`，以及 `session/event` 里读取的 `tool/call`、`tool/result`、`jobs.events`、`workflow/end`、`tool-workflow/run-start`。
- 该区间的改动都是新增，且不在本插件的路径上：`plugin:` 记录命名空间、`job/registered`、`job/settled`、`working-directory/change`，以及 `connection.operator` 改名为 `connection.browserPeer`。

<h3 id="cn-v044">✅ 验证</h3>

- 真实运行的 `0.2.1-alpha.3` 上，加载器只拒了 `browser-use` 与 `browser-use-playwright-mcp` 两行，本插件未被拒载，也没有动用任何版本豁免。
- 宿主半边实测：`/health` 报 `guiAvailable: true`、`eventErrors: 0`；`/config`、`/sounds`、`/update` 均返回 200；`/pull` 返回当天 6 条真实记录，含完成、失败与一条仍待回答的提问。
- 客户端半边实测：页面客户端插件包内含 `@idoall/dsh-notify/client.js`，实际下发的合并包带 `settings.section` 与 `shell.overlay` 注册。
- `npm run verify`：静态检查、**110/110** 测试、构建、打包前置检查。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.4
```

本版只有兼容性声明变化，在 `0.2.1-alpha.3` 上运行的 `0.4.3` 功能上无需升级；这条命令只是把 npm 上的版本与声明同步到最新。

<h3 id="en-v044">🔌 Compatibility</h3>

- Compatible with DeepSeek Harness `0.2.1-alpha.3`: `dsh.compatibility.dshReleases` gains that line; the existing `>=0.1.7-rc.1 <0.3.0` requirement already admitted it, so no range widening was needed.
- `0.2.1-alpha.3` needs no code change: comparing every interface this plugin binds, none of them moved — `requestRejection`, `webServer.register`/`tapIndex`, the `settings.section` and `shell.overlay` seats, `slots.inject`, `uiSession.sessionStatus`, and the `tool/call`, `tool/result`, `jobs.events`, `workflow/end` and `tool-workflow/run-start` payloads it reads from `session/event`.
- What the range added is additive and off this plugin's paths: the `plugin:` record namespace, `job/registered`, `job/settled`, `working-directory/change`, and the `connection.operator` → `connection.browserPeer` rename.

<h3 id="en-v044">✅ Verification</h3>

- On a real `0.2.1-alpha.3` runtime the loader refused only the `browser-use` and `browser-use-playwright-mcp` rows: this plugin was neither refused nor granted an exact-version exemption.
- Host half measured live: `/health` reported `guiAvailable: true` and `eventErrors: 0`; `/config`, `/sounds` and `/update` all answered 200; `/pull` returned six real records from that same day, spanning a completion, a failure and a question still awaiting an answer.
- Client half measured live: the page lists `@idoall/dsh-notify/client.js` in its plugin bundle, and the served bundle carries the `settings.section` and `shell.overlay` registrations.
- `npm run verify`: static source checks, **110/110** tests, build, and package precondition checks.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.4
```

This release changes compatibility declarations only; a `0.4.3` already running on `0.2.1-alpha.3` needs no functional upgrade, and this command merely syncs the npm version and declaration.
