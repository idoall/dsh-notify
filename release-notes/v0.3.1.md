<h3 id="cn-v031">通知可靠性与审批语义修复</h3>

### 修复

- **声音与可见通知一致**：只有通知成功进入已启用的可视 Toast 队列后才播放自动提示音；同一轮轮询的多条通知只播放一次。未能进入队列的卡片不会被错误标记为已处理，后续仍可投递。
- **未处理交互恢复**：Toast 浮层重新挂载时，宿主仍报告为未处理的审批、需要回复与计划待审会静默恢复；已结算的旧记录不会被重播。
- **审批颜色统一**：计划待审现在与执行审批一样使用橙色，表示“现在需要你作决定 / 批准后才能继续”；普通需要回复继续使用蓝色。

### 已验证

- 真实待处理交互验收确认：原生橙色状态标记、右上角 Toast、提示音、点击跳转和左侧会话自动显现同时正常；交互处理后 pending 状态与投递记录同步清除。
- 已现场确认计划待审 Toast 为橙色。

### 已知边界

- DSH 重启会清空原生运行时 pending interaction；重启前尚未处理、且宿主不再报告的交互不会恢复左侧橙点或 Toast。这是 DSH 原生状态恢复边界，不由本插件伪造或持久化。

<h3 id="en-v031">Notification reliability and approval-semantics fixes</h3>

### Fixed

- **Sound matches visible delivery**: automatic audio plays only after a notification is admitted to an enabled visual Toast queue. One polling batch produces one cue. A rejected card is not incorrectly marked delivered and remains eligible for a later delivery attempt.
- **Open interaction recovery**: when the Toast overlay remounts, approvals, questions, and plan reviews that the Host still reports as open are restored silently. Settled historical records are not replayed.
- **Consistent approval colour**: plan reviews now use the same amber colour as execution approvals, meaning “your decision is needed before work can continue.” Ordinary questions remain blue.

### Verified

- A live pending-interaction acceptance confirmed the native amber marker, Toast, sound, Toast navigation, and automatic left-sidebar reveal together; clearing the interaction cleared the pending state and delivery record.
- A live plan-review Toast was confirmed amber.

### Known boundary

- A DSH restart clears native in-process pending interactions. An interaction that was pending before restart but is no longer reported by the Host cannot restore its native amber marker or Toast. This is a DSH native state-recovery boundary; the plugin does not fabricate or persist it.
