<h3 id="cn-v0412">DSH Notify 0.4.12</h3>

跟进当前运行的 DSH `0.2.2-alpha.3`，修复客户端加载生命周期与发布信息同步。

兼容 DeepSeek Harness `0.2.2-alpha.3`；宿主版本范围保持 `>=0.1.7-rc.1 <0.3.0`。npm DSH `latest` 当前是 `0.2.1-rc.5`，本次验证的是 `alpha` 通道，不将未经启动验证的 RC 加入明确兼容列表。

### 修复与调整

- 客户端 `apply` 改为不可作为构造器调用的箭头函数，并返回可重复安全调用的清理函数。原入口是普通 function，Cordis 可将它当构造器调用而忽略清理返回值；普通对象若进入 effect 路径则报 `Invalid effect`。设置与浮层注册在卸载时正确清理；通知逻辑不变。
- 新增 `0.2.2-alpha.3` 兼容声明。对比 alpha.2 的发布包：renderer、session UI、connection、webserver、jobs、session、agent、agent-loop、workflow 的构建未变；设置新增可选图标挂载点，布局新增折叠横屏适配，模块加载器调整增量协调逻辑，现有通知接口仍保留。
- 修正锁文件中遗留的 DSH peer `<0.2.0` 上限，与清单的 `<0.3.0` 同步。锁定的传递依赖 Zod 从 `4.6.5` 升至 `4.6.7`，消除本次 `npm audit` 报告的高危公告；不修改宿主或其他工作区依赖。
- 发布检查新增中英文 README 的当前版本、DSH 徽章、兼容表、发布命令，以及 CHANGELOG、双语 Release 和锁文件一致性校验。

### 验证与边界

- 静态检查、**118 个自动化测试**、构建与打包检查通过；新增真实 Cordis 客户端加载/卸载测试与发布信息回归测试。
- 当前宿主的 Host 契约检查通过；实时 Client inspect 确认 `shell.overlay` 中 `dsh-notify-toast` 为 active。现有安装未升级，本次没有修改 profile。
- 自动化浏览器访问当前 GUI 返回 HTTP 401，因此不宣称本版设置页、手机视口、声音或端到端通知已完成新的视觉实测。README 截图为此前版本的验证记录。
- 发布后下载 npm tarball，核对清单、中英文 README、CHANGELOG、bundle patch 和全部构建文件，并核对 npm `latest`、GitHub Release、标签及附件。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.12
```

<h3 id="en-v0412">DSH Notify 0.4.12</h3>

Tracks the running DSH `0.2.2-alpha.3`, fixing client lifecycle handling and release metadata alignment.

Compatible with DeepSeek Harness `0.2.2-alpha.3`; the host requirement remains `>=0.1.7-rc.1 <0.3.0`. The npm DSH `latest` channel currently points to `0.2.1-rc.5`; this review targets `alpha` and does not add an unbooted RC to the explicitly verified list.

### Fixes and changes

- Client `apply` is now a non-constructible arrow function returning an idempotent disposer. Cordis can treat the old ordinary function as a constructor and ignore its cleanup return; a plain object passed through the effect path instead throws `Invalid effect`. Unloading cleans up settings and overlay registrations; notification logic is unchanged.
- Declares `0.2.2-alpha.3` compatible. Compared with published alpha.2 packages, renderer, session UI, connection, webserver, jobs, session, agent, agent-loop and workflow builds are unchanged. Settings adds optional navigation-icon slots, layout adds folded-landscape handling, and the module loader adjusts incremental reconciliation while preserving the notification interfaces.
- Synchronizes the lockfile's stale DSH peer ceiling `<0.2.0` with the manifest's `<0.3.0`. Updates locked transitive Zod from `4.6.5` to `4.6.7` to resolve the high-severity advisory reported by `npm audit`; no host or other workspace dependencies are modified.
- Release checks cover both READMEs' current version, DSH badge, compatibility row and release commands, plus CHANGELOG, bilingual Release notes and lockfile consistency.

### Verification and limits

- Static checks, **118 automated tests**, build and package checks pass, including real Cordis client load/unload tests and release metadata regressions.
- Host contracts were inspected on the running host; live Client inspection shows `dsh-notify-toast` active in `shell.overlay`. The existing installation was not upgraded and no profile changes were made.
- The automated browser received HTTP 401 from the GUI, so this release does not claim a fresh settings-page, mobile, sound or end-to-end notification visual test. README screenshots document earlier verification.
- Post-publication acceptance downloads the npm tarball and checks its manifest, both READMEs, CHANGELOG, bundle patch and all build files, as well as npm `latest`, GitHub Release, tag and assets.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.12
```
