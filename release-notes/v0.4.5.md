声明兼容 DeepSeek Harness `0.2.1-alpha.4`，代码零改动；正在运行的 `0.4.4` 本来就已在 `0.2.1-alpha.4` 上正常通知。

<h3 id="cn-v045">🔌 兼容性</h3>

- 兼容 DeepSeek Harness `0.2.1-alpha.4`：`dsh.compatibility.dshReleases` 增加这一行；`>=0.1.7-rc.1 <0.3.0` 本来就接纳它，范围无需放宽，也不需要版本豁免。
- `0.2.1-alpha.4` 不需要代码改动：插件绑定的每个包在这一版之间逐字节相同——`requestRejection`、`webServer.register`/`tapIndex`、`settings.section` 与 `shell.overlay` 座位、`slots.inject`、`uiSession.sessionStatus`、`session/event` 读取的各类事件、`jobs.events`、`workflow/end`、`tool-workflow/run-start` 全都在原处。
- 唯一有改动的是 `dsh-client-ui-settings-general`，且改动不在本插件的路径上：新增「宿主版本变更提示」及其本地化文案，另有一处纯外观的 CSS 变量重编号。

<h3 id="cn-v045">✅ 验证</h3>

- 真实运行的 `0.2.1-alpha.4` 上，加载器只拒了 `browser-use` 与 `browser-use-playwright-mcp` 两行，本插件未被拒载，也没有动用任何版本豁免。
- 宿主半边实测：`/health` 报 `guiAvailable: true`、`eventErrors: 0`；`/config`、`/sounds`、`/update` 均返回 200。
- 客户端半边实测：页面客户端插件包内含 `@idoall/dsh-notify/client.js`，实际下发的合并包 200（4.4 MB），带 `settings.section` 与 `shell.overlay` 注册。
- `npm run verify`：静态检查、**110/110** 测试、构建、打包前置检查。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.5
```

本版只有兼容性声明变化，在 `0.2.1-alpha.4` 上运行的 `0.4.4` 功能上无需升级；这条命令只是把 npm 上的版本与声明同步到最新。

<h3 id="en-v045">🔌 Compatibility</h3>

- Compatible with DeepSeek Harness `0.2.1-alpha.4`: `dsh.compatibility.dshReleases` gains that line; the existing `>=0.1.7-rc.1 <0.3.0` requirement already admitted it, so no range widening and no exemption were needed.
- `0.2.1-alpha.4` needs no code change: every package this plugin binds is byte-identical across this release — `requestRejection`, `webServer.register`/`tapIndex`, the `settings.section` and `shell.overlay` seats, `slots.inject`, `uiSession.sessionStatus`, the `session/event` events it reads, `jobs.events`, `workflow/end` and `tool-workflow/run-start` all stayed where they were.
- The one package that did change, `dsh-client-ui-settings-general`, changed off this plugin's paths: it adds a Host release change prompt with its locale strings, plus a purely cosmetic renumbering of bundled CSS variables.

<h3 id="en-v045">✅ Verification</h3>

- On a real `0.2.1-alpha.4` runtime the loader refused only the `browser-use` and `browser-use-playwright-mcp` rows: this plugin was neither refused nor granted an exact-version exemption.
- Host half measured live: `/health` reported `guiAvailable: true` and `eventErrors: 0`; `/config`, `/sounds` and `/update` all answered 200.
- Client half measured live: the page lists `@idoall/dsh-notify/client.js` in its plugin bundle, and the served combo bundle answered 200 (4.4 MB) with the `settings.section` and `shell.overlay` registrations.
- `npm run verify`: static source checks, **110/110** tests, build, and package precondition checks.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.5
```

This release changes compatibility declarations only; a `0.4.4` already running on `0.2.1-alpha.4` needs no functional upgrade, and this command merely syncs the npm version and declaration.
