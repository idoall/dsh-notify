| 插件版本 | 已验证的 DeepSeek Harness | npm 发布状态 |

| **`0.4.0`** | **`0.1.7-rc.2`（最新 RC）** | 本次发布（`latest`） |
| `0.3.4` | `0.1.7-rc.1` | 已发布 |

**兼容范围未变**：`>=0.1.7-rc.1 <0.2.0`。本版在 `0.1.7-rc.2` 上完成真机验证，`0.1.7-rc.1` 继续声明兼容。

### 为什么发这个版本

`0.3.4` 解决的是**「什么时候提醒你」**；本版补上**「我装的是不是最新的」**——参考 [dsh-lan-guard](https://github.com/idoall/dsh-lan-guard) 设置页的局域网访问里的在线版本检测，把同一行放到 **设置 → 通知**。

此前要知道有没有新版本，只能自己去 npm 或仓库看。现在设置页直接给出结论，并且**不会替你做任何决定**：不自动安装、不自动重启。

### 改了什么

- **设置页新增版本检测行**（位于页头下方、卡片上方）：显示当前版本与 npm 最新版本的关系，并提供**检查更新**、GitHub、更新日志、反馈 Issue 四个入口。
  - `v0.4.0 ✓ 最新`：绿色，已是最新。
  - `v0.4.0 ➔ v0.5.0`：强调色，同时给出可复制的升级命令。
  - `v0.4.0 · 检查失败`：中性色。**registry 不可达时绝不把当前版本谎称为最新**。
- **宿主新增只读路由** `GET /plugins/dsh-notify/update`：沿用本插件既有的鉴权与 CSRF 规则（GET 只读，非 GET 才校验同源），带 6 小时缓存；**检查更新**用 `?force=1` 绕过缓存。失败的查询同样会被缓存，因此离线时不会每次开设置页都去敲 registry。
- **版本比较自己实现**：约 30 行 semver 算术（含预发布标识符比较），不引入 `semver` 依赖——本插件运行时依赖只有 DSH peer。
- **发现新版本时的面板**：给出 `dsh plugin --profile web add @idoall/dsh-notify@<版本>` 与复制按钮，并明确写出「本插件不会自动安装，也不会重启 dsh：执行上面的命令后，需要你手动重启一次 dsh 才生效」。没有新版本时不显示该面板。
- **复制失败会如实说明**：浏览器没有剪贴板 API 时提示「复制失败，请手动选择文本复制」，不会谎报「已复制」。
- 配置 schema、设置项与存储格式**未改动**。

![设置 → 通知 的版本检测行](https://raw.githubusercontent.com/idoall/dsh-notify/v0.4.0/assets/version-check.png)

### 谁受影响

- **所有人**：设置页多了一行版本状态，不需要任何配置。
- **不想要这个功能的人**：它不发起任何写入，不产生后台轮询——只在打开设置页时查一次（6 小时内复用），以及你点**检查更新**时再查一次。若 registry 不可达，也只是显示「检查失败」。
- **网络受限环境**：查询有 5 秒超时且失败被缓存，不会拖慢设置页；检测失败不影响通知本身。
- **配置无需迁移**：`dataDir`、提示音、样式、位置等偏好原样继续生效。

### 兼容性与升级

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.0
```

- **宿主半边需要重启 `dsh web`** 才会加载本版——`/plugins/dsh-notify/update` 路由在宿主侧。重启前设置页会显示「检查失败」（路由不存在），这是预期现象。
- **客户端半边刷新页面即生效**。
- 未配置绝对 `dataDir` 时，设置页仍显示「设置不落盘」，偏好只保存在当前进程。

### 验证

- `npm run verify`：静态检查（`tscheck.mjs` + `tsc --noEmit`）、**108/108** 测试（自 `0.3.4` 的 92 条增加 16 条）、Host/Client 构建、npm 包前置检查。
- 新增 16 条用例：
  - **8 条版本检测单测**：semver 排序（`rc.1` < `rc.2` < `rc.10` < 正式版）、构建元数据、不可解析字符串一律「相等」（因此绝不会谎报有更新）；registry 503 / 无 `version` 字段 / 抛错 / 运行时无 `fetch` 都归为 `registry_unavailable`；缓存命中、TTL 过期、`force` 绕过；失败结果同样被缓存。
  - **2 条路由用例**：读的是随包发布的 `package.json` 版本；普通请求走缓存、`force=1` 重新查询；鉴权拒绝时**根本不触达 registry**；registry 不可用时仍返回 200 并带 `error`，而不是让设置页报错。
  - **3 条 jsdom 设置页用例**：三种状态的文案与色调、三个仓库链接、升级面板只在真有新版本时出现、无剪贴板时如实报「复制失败」。
  - **3 条文案用例**：版本芯片不会把失败显示成「最新」。
- **真机验证**：在 `/tmp` 下隔离的 `DSH_HOME`（**不触碰使用者 profile**）中，用官方 `web` 模板建 profile，以 `link:` 安装本插件，启动 DSH `0.1.7-rc.2`：
  - `/plugins/dsh-notify/health` 返回 `guiAvailable: true`、`preferences: file`、`eventErrors: 0`。
  - `/plugins/dsh-notify/update` 走**真实 npm registry** 返回 `{"current":"0.4.0","latest":"0.3.4","hasUpdate":false,"error":null}`——npm 上的 `0.3.4` 比本地的 `0.4.0` 旧，因此正确地**不**报「有更新」；`?force=1` 触发第二次真实查询。
  - 设置页实际渲染出 `v0.4.0 ✓ 最新`（绿色）与三个仓库链接，无升级面板。

### 限制

- **不做自动更新**：本插件不安装、不重启，只报告并给出可复制命令——这是设计边界，不是缺失。
- **版本号来自随包发布的 `package.json`**：若安装目录被改动或缺少该文件，芯片退化为 `v0.0.0` 比较（不会崩溃）。
- **依赖公共 npm registry**：无法访问 `registry.npmjs.org` 时只会显示「检查失败」；不提供镜像或自定义源配置。
- **通知记录仍是内存态**：已结算历史不会在刷新、浮层重挂载或 DSH 重启后重播；突发超过缓冲区容量（50 条）时，最旧的未投递记录会被丢弃。
- **本版在隔离 profile 上完成真机验证**：使用者现有的 web profile 仍是 `0.3.3`，执行 `dsh plugin --profile web add @idoall/dsh-notify@0.4.0` 并重启 `dsh web` 后本版才生效。

### Why this release exists

`0.3.4` answered **"when does it tell you"**. This one answers **"am I still on the newest one"** — the same online version check the reference [dsh-lan-guard](https://github.com/idoall/dsh-lan-guard) settings page offers for 局域网访问, now in **Settings → Notifications**.

Until now the only way to learn about a newer version was to go and look. The settings page now states the answer, and it **decides nothing for you**: it never installs and never restarts.

### What changed

- **A version row in the settings page** (below the header, above the cards): the running version against npm's newest, with **检查更新**, GitHub, Changelog and Issues.
  - `v0.4.0 ✓ 最新` — green, already newest.
  - `v0.4.0 ➔ v0.5.0` — attention colour, plus a copyable upgrade command.
  - `v0.4.0 · 检查失败` — neutral. **An unreachable registry is never presented as "newest".**
- **A read-only Host route**, `GET /plugins/dsh-notify/update`, behind the plugin's existing auth and CSRF rules (GET is read-only; only non-GET checks same-origin), with a six-hour cache. **检查更新** bypasses it with `?force=1`. A failed lookup is cached too, so an offline host is not asked again on every settings visit.
- **The comparison is implemented here**: ~30 lines of semver arithmetic (including prerelease identifier ordering) instead of adding `semver` as a dependency — this plugin's only runtime dependencies are DSH peers.
- **The upgrade panel** appears only when there is something to install: `dsh plugin --profile web add @idoall/dsh-notify@<version>` with a copy button, and an explicit sentence that the plugin does not auto-install and does not restart DSH, so the restart is yours.
- **A failed copy says so**: without a clipboard API the page reports 复制失败，请手动选择文本复制 rather than claiming 已复制.
- The config schema, settings, and stored format are **unchanged**.

![The version row in Settings → Notifications](https://raw.githubusercontent.com/idoall/dsh-notify/v0.4.0/assets/version-check.png)

### Who is affected

- **Everyone**: one extra status row, no configuration required.
- **Anyone who does not want it**: it performs no writes and no background polling — one lookup when the settings page opens (reused for six hours) and one more when you press **检查更新**. An unreachable registry only renders 检查失败.
- **Restricted networks**: the lookup has a 5 s timeout and failures are cached, so the settings page is never held up, and a failed check does not affect notifications.
- **No migration.** `dataDir`, sound, style, position, and every other preference keep working as they are.

### Compatibility and upgrade

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.0
```

- **The Host half needs a `dsh web` restart** to load this version — the `/plugins/dsh-notify/update` route lives on the Host side. Until that restart the row shows 检查失败 (the route does not exist yet), which is expected.
- **The client half takes effect on a page refresh.**
- Without an absolute `dataDir`, the settings page still reports "settings are not persisted" and preferences live only for the current process.

### Verification

- `npm run verify`: static source checks (`tscheck.mjs` + `tsc --noEmit`), **108/108** tests (16 more than `0.3.4`'s 92), Host/Client build, and npm package precondition checks.
- Sixteen new tests:
  - **8 version-check unit tests**: semver ordering (`rc.1` < `rc.2` < `rc.10` < release), build metadata, and an unparsable string comparing as equal (so it can never claim an update); registry 503, a missing `version` field, a thrown error, and a runtime without `fetch` all become `registry_unavailable`; cache hit, TTL expiry, and `force` bypass; a failed lookup is cached too.
  - **2 route tests**: the version is read from the shipped `package.json`; a plain request is served from the cache while `force=1` asks again; a refused request **never reaches the registry**; an unreachable registry still answers 200 with an `error` field instead of breaking the settings page.
  - **3 jsdom settings tests**: the wording and tone of all three states, the three repository links, the upgrade panel appearing only when there is something to install, and a clipboard-less browser reporting 复制失败.
  - **3 wording tests**: the chip never renders a failed lookup as "newest".
- **Real-machine verification** in an isolated `DSH_HOME` under `/tmp` (the user's profile is never touched): a profile created from the shipped `web` template, the plugin installed with `link:`, and DSH `0.1.7-rc.2` booted:
  - `/plugins/dsh-notify/health` answered `guiAvailable: true`, `preferences: file`, `eventErrors: 0`.
  - `/plugins/dsh-notify/update` reached the **real npm registry** and returned `{"current":"0.4.0","latest":"0.3.4","hasUpdate":false,"error":null}` — npm's `0.3.4` is older than this build's `0.4.0`, so it correctly does **not** claim an update; `?force=1` produced a second real lookup.
  - The settings page really rendered `v0.4.0 ✓ 最新` (green) with the three repository links and no upgrade panel.

### Limitations

- **No auto-update.** The plugin does not install and does not restart; it reports and offers a copyable command. That is the design boundary, not a missing feature.
- **The version comes from the shipped `package.json`.** If that file is missing or edited in the install directory, the chip degrades to a `v0.0.0` comparison rather than crashing.
- **It depends on the public npm registry.** Without access to `registry.npmjs.org` the row only shows 检查失败; there is no mirror or custom-registry setting.
- **Notification records remain memory-only:** settled history is not replayed after a refresh, an overlay remount, or a DSH restart, and a burst larger than the buffer (50 records) drops the oldest undelivered record.
- **Real-machine verification was done on an isolated profile:** an existing web profile still runs `0.3.3` until it is upgraded with `dsh plugin --profile web add @idoall/dsh-notify@0.4.0` and `dsh web` is restarted.
