<h3 id="cn-v0417">DSH Notify 0.4.17</h3>

修复 DSH `0.2.3-alpha.2` 带来的两处断裂。通知、提示音与交互行为本身未改。

兼容 DeepSeek Harness `0.2.3-alpha.2`；宿主范围保持 `>=0.1.7-rc.1 <0.3.0`。

### 🔧 修复

- **路由不再因 `Connection.requestRejection` 被移除而崩**。DSH `0.2.3-alpha.1` 把 HTTP admission 移进了 WebServer：`register(route)` 接受 `auth: 'anonymous' | 'required' | 'deny'`（默认 `required`），放行后的 Peer 作为处理函数第三个参数传入，`Connection.requestRejection` 被删除。现在每条路由都显式声明 `auth: 'required'`，并只在服务仍提供该方法时才调用它。没有这个修复，`0.4.16` 在当前宿主上会在处理函数里抛 `requestRejection is not a function`，`/pull`、`/config`、`/sounds`、`/update`、`/health` 对已登录页面全部失败。
- **挂载判断不再依赖那个被删掉的方法**。反射式组合路径原先用 `connection?.requestRejection` 决定是否挂载，新宿主没有它，于是根本不注册路由、报 `guiAvailable: false`。现在以「connection 服务存在」为条件，由路由的 `auth` 负责准入。
- **卡片内回答跟随拆分后的 Session status 服务**。`0.2.3-alpha.1` 把统一状态快照移到独立的 `uiSession.sessionStatus` 服务；插件若未注入该服务就读它，会抛 `cannot get property "uiSession.sessionStatus" without inject`。浮层原先优先读它，导致待回答交互接线中断。现在 `resolvePendingSource` 优先用同一服务上的只读 `uiSession.pendingInteractions`（无需注入），保留旧 `sessionStatus` 快照作为 `0.1.7`–`0.2.2` 的回退，仅在别无选择时返回 pre-`0.1.7` 的裸 Map，并容忍任一表面抛出。

### ⚠️ 其他调整

- 声明兼容 `0.2.3-alpha.2`，保留此前每一个已实测版本。
- 逐条读取安装包内的升级指南：`v0.2.2-rc.5`（14 项，`rc.5` → `0.2.3-alpha.1`）与 `v0.2.3-alpha.1`（1 项，`alpha.1` → `alpha.2`）。本次安装还新带了 `v0.2.2-rc.2`（13 项），其中两项正是上面修掉的断裂，其余均为本插件不使用的接口。
- **Node.js 门槛更新**：当前 DSH 要求 24.x 系列中的 `24.22.3` 或更高，或 `26.13.1` 或更高（此前写作 `24.9.0`）。插件自身 `engines.node` 仍为 `>=20`，那是它自己代码的下限。
- 客户端产物元信息改为可选，本插件继续使用旧预设 bundle（不带 `meta`），仍可正常加载；唯一差别是 Modules 不再移除旧预设注入的 `<style data-plugin>`，禁用插件后样式会保留到刷新页面。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.17
```

<h3 id="en-v0417">DSH Notify 0.4.17</h3>

Fixes two breaks introduced by DSH `0.2.3-alpha.2`. Notifications, sounds and interactions are unchanged.

Compatible with DeepSeek Harness `0.2.3-alpha.2`; the host requirement remains `>=0.1.7-rc.1 <0.3.0`.

### 🔧 Fixed

- **Routes no longer crash on the removed `Connection.requestRejection`.** DSH `0.2.3-alpha.1` moved HTTP admission into the WebServer: `register(route)` takes `auth: 'anonymous' | 'required' | 'deny'` (default `required`), the admitted Peer arrives as the handler's third argument, and `Connection.requestRejection` is gone. Every route now declares `auth: 'required'` and calls `requestRejection` only when the service still has it. Without this, `0.4.16` threw `requestRejection is not a function` inside the handler on the current host, so `/pull`, `/config`, `/sounds`, `/update` and `/health` all failed for authenticated page loads.
- **Route mounting no longer requires that removed method.** The reflective composition path tested `connection?.requestRejection` before mounting, so a host without it registered no routes and reported `guiAvailable: false`. The guard is now the connection service itself, with the route's `auth` owning admission.
- **In-toast answering follows the split Session status service.** `0.2.3-alpha.1` moved the status snapshot to its own `uiSession.sessionStatus` service, which throws `cannot get property "uiSession.sessionStatus" without inject` unless the plugin injects it. The overlay read it first, which broke the pending-interaction wiring. `resolvePendingSource` now prefers the read-only `uiSession.pendingInteractions` observable (no injection needed), keeps the older `sessionStatus` snapshot as the fallback for `0.1.7`–`0.2.2`, returns a bare pre-`0.1.7` map only when nothing better exists, and tolerates either surface throwing.

### ⚠️ Also changed

- Declares `0.2.3-alpha.2` compatible while preserving every previously verified release.
- Read the installed guides for the whole span: `v0.2.2-rc.5` (14 items, `rc.5` → `0.2.3-alpha.1`) and `v0.2.3-alpha.1` (1 item, `alpha.1` → `alpha.2`). This install also ships a `v0.2.2-rc.2` section (13 items) that earlier installs omitted; two of those are the breaks fixed here.
- **Node.js floor.** Current DSH requires Node.js `24.22.3` or newer in the 24.x line, or `26.13.1` or newer (the README said `24.9.0`). The plugin's own `engines.node` stays `>=20`.
- Client module metadata is now optional. This plugin keeps its earlier-preset bundle (no `meta`) and still loads; the only consequence is that Modules no longer removes an earlier preset's `<style data-plugin>` element, so disabling the plugin leaves its styles until the page reloads.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-notify@0.4.17
```
