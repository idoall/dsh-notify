<h3 id="cn-v0.2.2">发布到 npm</h3>

本插件现在发布在 npm 上：**`@idoall/dsh-notify`**。

- **为什么要带 scope**：无 scope 的 `dsh-notify` 属于**另一位作者**（一个 Windows 托盘通知插件），裸装会装错包。请始终用 `dsh plugin --profile web add @idoall/dsh-notify@latest` 安装。
- **行为没有任何变化**：插件内部身份（cordis 名、`dsh-notify` 挂载 id、`/plugins/dsh-notify/*` 路由、CSS 类名）保持原来的短名，profile 配置与设置项不受影响，测试也不用改。
- **npm 页面现在有截图**：`assets/` 随包发布，README 里的四张图在 npm 上能正常显示。

### 其他

- 0.2.2 由维护者本地手动发布一次；之后的版本只要改 `package.json` 的版本、写 `release-notes/v<版本>.md`、推 `v*` tag——GitHub Actions 会自动测试、打包、通过 OIDC 发布到 npm 并创建 Release。
- **宿主**侧需要把插件重新装/重新 link 成 `@idoall/dsh-notify` 并重启 DSH；**客户端**硬刷新即可。

<h3 id="en-v0.2.2">Published to npm</h3>

The plugin is now on npm as **`@idoall/dsh-notify`**.

- **Why the scope**: the unscoped `dsh-notify` name belongs to a **different** author (a Windows tray/toast plugin), so a bare install would pull the wrong package. Install with `dsh plugin --profile web add @idoall/dsh-notify@latest`.
- **No behaviour change**: the plugin's internal identity (cordis name, the `dsh-notify` mount id, the `/plugins/dsh-notify/*` routes, every CSS class) keeps its short spelling, so profile config, settings keys and the test suite are untouched.
- **Screenshots on the package page**: `assets/` now ships inside the tarball, so the four README images render on npm.

### Chores

- 0.2.2 is published once by hand; later versions only need a version bump, a `release-notes/v<version>.md`, and a `v*` tag — GitHub Actions tests, packs, publishes through OIDC and creates the Release.
- **Host**: re-add the plugin as `@idoall/dsh-notify` and restart DSH. **Client**: a hard refresh is enough.
