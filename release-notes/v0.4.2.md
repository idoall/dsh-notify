修复「走了审批的任务不再通知完成」，并声明兼容 DeepSeek Harness `0.2.0-rc.2`。

<h3 id="cn-v042">🐞 修复</h3>

- **向你要过审批的任务，完成时重新会通知。** 自 `0.3.2` 起，只要一个回合里出现过执行审批（`approval/asked`）或计划审批（`exit_plan_mode`），这个回合的完成通知就被永久压掉。当时的假设是：交互暂停会结束该回合，用户决定后工作会在**新回合**里继续，所以旧回合的结束不算完成。
- **DSH 从来不是这样。** `approval.request()` 必须处于打开的回合内，并在原地等待决定后才追加 `approval/decided`；`exit_plan_mode` 把结论交回同一回合。也就是说，接着干活的回合就是提问的那个回合，它的 `turn/end` 就是用户任务的完成。
- 新规则只有一句：**门禁只在「还没等到人回答」时压住该回合的完成通知。** 审批被决定、被门禁的 tool 返回结果，门禁即解除；回合结束时仍无人回答才会压掉——这是真实 DSH 不会出现的情形，保留它只是防守式读法。
- 普通 `ask_user_question` 依旧不压：它本身可能就是任务的最后一步。

<h3 id="cn-v042">🔌 兼容性</h3>

- `dsh.compatibility.dshReleases` 新增 `0.2.0-rc.2` 与 `0.2.1-alpha.1`（保留 `0.2.0-rc.1`、`0.1.7-rc.2`、`0.1.7-rc.1`）。
- 兼容范围本身**不需要放宽**：`>=0.1.7-rc.1 <0.3.0` 在 DSH 的 `includePrerelease` 判定下本来就接纳 `0.2.0-rc.2` 与 `0.2.1-alpha.1`——这正是 `0.4.1` 没有出现在启动 skip 列表里的原因。
- `0.2.0-rc.2` 新增的可选 `ask_user_question` timed 模式无需宿主改动：前台等待超时返回 pending 结果、工具调用即已结算，回合继续后照常由该回合的结束发出完成通知；默认仍是阻塞式 legacy 工具。

<h3 id="en-v042">🐞 Fixed</h3>

- **A task that asked for your approval is announced again when it finishes.** Since `0.3.2`, any turn containing an execution approval (`approval/asked`) or a plan review (`exit_plan_mode`) had its completion withheld forever. The assumption was that the interactive pause ended that turn and the work resumed in a **new** one, so the old turn's end was not a completion.
- **DSH never does that.** `approval.request()` requires an open turn and awaits its outcome in place before appending `approval/decided`; `exit_plan_mode` returns its verdict to the same turn. The turn that resumes is the turn that asked, and its `turn/end` is the user's task finishing.
- The new rule is one sentence: **a gate withholds its turn's completion only while the human still owes an answer.** A decided approval, or the gated tool returning its result, releases the gate; an end that leaves it open is kept as the safe reading — real DSH does not produce it.
- An ordinary `ask_user_question` still never suppresses: it may itself be the last operation of the task.

<h3 id="en-v042">🔌 Compatibility</h3>

- `dsh.compatibility.dshReleases` gains `0.2.0-rc.2` and `0.2.1-alpha.1` (`0.2.0-rc.1`, `0.1.7-rc.2`, `0.1.7-rc.1` stay declared).
- The requirement itself needed **no widening**: `>=0.1.7-rc.1 <0.3.0` already admits both `0.2.0-rc.2` and `0.2.1-alpha.1` under DSH's `includePrerelease` evaluation — which is exactly why `0.4.1` never appeared in the startup skip list.
- The optional `ask_user_question` timed mode added in `0.2.0-rc.2` needs no host change: its foreground wait returns a pending result, the call is settled, and the continuing turn still announces its own completion. The default remains the blocking legacy tool.
- `0.2.1-alpha.1` (`dsh-v0.2.0-rc.2..dsh-v0.2.1-alpha.1`, 266 commits) needs **no code change either**: the bound packages differ only by version bumps and the repository-wide removal of the `invariant` companion modules, which no runtime path loads. The one real source change is `ui-layout` adding the **new** `shell.bottom` seat and its `.frame` grid row; the `shell.overlay` seat this plugin mounts into, its `.overlayLayer`, and the `[data-conversation-scroll]` anchor the toast measures are untouched.
